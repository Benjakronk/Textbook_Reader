# Textbook Reader — plan

A read-only markdown reader designed as a digital textbook for students. Reuses
the rendering and reading features of the parent project but cuts everything
related to authoring.

## Goals

- Read-only. No editing, saving, renaming, deleting, uploading, or history.
- Static content: a structured `content/` folder of `.md` files is the textbook.
- Strong reading affordances: themes, focus mode, font/family/width controls,
  TOC with scroll-spy, search, internal links/embeds/footnotes/callouts, graph
  view, page preview / print.
- Study features: bookmarks, last-position recall, "next/previous lesson",
  per-document reading progress, optional offline mode.
- Easy deployment for a teacher: drop on a static host (GitHub Pages, school
  LMS asset folder, USB stick, local file server).

## Non-goals

- Multi-user accounts, server-side state, comments/annotations, quizzes.
- Authoring tools (those live in the parent app).

## Architecture options

**Option A — Static site + build step (recommended).**

- A `build.py` walks `content/` once and emits a small set of static JSON
  artifacts under `static/data/`:
  - `index.json` — file tree, per-file metadata (title, tags, headings,
    word count, mtime, links/backlinks).
  - `search.json` — concatenated text per file (or n-gram index) for
    in-browser full-text search.
- The frontend (`static/index.html` + `app.js` + `style.css`) is plain HTML/JS
  and fetches the JSON artifacts at startup.
- Pros: zero backend, deploys anywhere, works fully offline if the JSON is
  cached. Privacy-friendly. Trivial for a teacher to host.
- Cons: needs a build step when content changes (one command, ~seconds).

**Option B — Tiny read-only Python server.**

- Slim down `server.py` to GET-only endpoints: `/api/tree`, `/api/file`,
  `/api/search`, `/api/index`. Drop everything mutating.
- Pros: no build step; index always reflects current content.
- Cons: needs Python on the host. Worse fit for shared deployment.

**Recommendation: Option A.** A class-sized textbook (≤200 files, ~5-10 MB
text) is fully searchable in the browser, and a teacher can drop the built
folder anywhere — no Python, no servers, no permissions. Service worker can
make the whole textbook installable / available offline.

## Suggested layout

```
Textbook_Reader/
  README.md                   # how to author content, build, deploy
  build.py                    # walks content/, emits static/data/*.json
  serve_dev.py                # local dev server (optional; `python -m http.server` works too)
  content/                    # the textbook (subject → topic → lesson)
    KRLE/
      Kristendom/
        bergprekenen.md
        evangeliene-tilblivelse.md
        ...
      Religionskritikk/
        ...
    _assets/                  # images referenced by markdown
  static/
    index.html
    app.js
    style.css
    icon.svg
    data/                     # generated by build.py — gitignored
      index.json
      search.json
    sw.js                     # optional: service worker for offline mode
```

Frontmatter convention (per file, optional):

```yaml
---
title: Bergprekenen
chapter: Kristendom
order: 3
tags: [jesus, etikk]
summary: Korte sammendrag av Bergprekenens hovedbudskap.
---
```

`build.py` reads frontmatter to drive sidebar ordering, breadcrumbs, summaries,
and the next/prev navigation. Files without `order` fall back to alphabetical.

## What to keep vs cut from the parent app

**Keep (port from `static/app.js`):**

- Markdown render pipeline: marked + DOMPurify + custom transforms (wikilinks,
  embeds, callouts, footnotes, highlight `==…==`, sub/sup, page-break HR,
  asset URL rewriting).
- Math (KaTeX) and Mermaid.
- TOC with scroll-spy. Backlinks panel.
- Theme palette (light/dark/sepia/print-style/etc.), font family + size,
  document max-width controls.
- Focus mode. Page preview. Print stylesheet.
- Search (full-text + filename) with multi-snippet results that jump to a
  specific occurrence — already implemented in the parent.
- Graph view (filtered to internal links).
- Recent files, tags panel, mobile/responsive layout.
- Persistent settings (theme, font, last-read position) via `localStorage`.

**Cut entirely:**

- Editor textarea, format toolbar, autocomplete.
- Save / rename / delete / upload / drag-drop / clipboard cut/paste files.
- Version history.
- Find & replace (in-document or project-wide).
- Edit-at-this-point, sync editor↔view, split mode, mode buttons.
- Daily-note creation, "new file" actions, file-tree mutations.
- Image upload, asset writing.

**Add (new):**

- Lesson navigation: top of each page shows breadcrumb (subject → topic →
  lesson), and footer shows "← Previous lesson · Next lesson →" using the
  ordering rules above.
- Bookmarks: per-page toggle, listed in a sidebar tab; persists in
  `localStorage`.
- Reading progress per file (read / unread / partial based on scroll depth +
  "mark as read" toggle); summary on the subject landing page.
- "Resume where I left off" across sessions.
- Optional offline mode via service worker pre-caching all JSON + assets.
- Print-friendly view that emits the whole subject or current lesson.

## Phased build

**Phase 1 — Scaffold and core reading.**
- Copy `static/index.html`, `static/app.js`, `static/style.css` from the
  parent into `Textbook_Reader/static/`, then strip everything tied to
  editing. Aim: load + render a markdown file, theme switch works, sidebar
  tree works, TOC works.

**Phase 2 — Build pipeline + search.**
- Write `build.py` to produce `index.json` and `search.json`. Frontend reads
  these instead of hitting `/api/*`. Implement client-side search with the
  existing snippet/jump UI.

**Phase 3 — Study features.**
- Lesson navigation, bookmarks, progress tracking, resume.

**Phase 4 — Polish + offline.**
- Graph view, mobile layout pass, service worker, deployment docs.

## Decisions

- **Architecture**: Option A — static site + build step.
- **Directory name**: `Textbook_Reader/`.
- **Content seeding**: copy `markdowns/KRLE/` from the parent into
  `Textbook_Reader/content/` for development.
- **Access**: fully public; no auth gating.
- **Branding**: deferred until after Phase 1.
